Synth Workspace Bridge

Pair this extension with your Synth Workspace page. The pairing token lets the extension trust that origin; it is not a provider key and nothing else is stored here.

1. Enable browser control

When Synth Workspace asks, the extension reads or acts in the tab you have open using Chrome's debugger protocol — the same mechanism DevTools uses. Actions are limited to normal http(s) pages; chrome:// pages, the Web Store and other extensions are refused. Chrome shows a “started debugging this browser” banner while an action runs and removes it when the action finishes.

  • No tab is controlled until an action is requested.
  • A fixed set of actions: list, open, read, describe, click, type, screenshot, close and activate. The page cannot ask the extension to run arbitrary code.
  • Password fields are never filled.
  • Actions still follow the assistant's approval setting in the workspace.
2. Allow provider requests

The extension can only reach the model-provider APIs named in its manifest: Anthropic, OpenAI, DeepSeek, Google Gemini, OpenRouter, Together, Groq, Mistral, xAI, Fireworks, Cerebras, SambaNova, Nebius, Hyperbolic, Perplexity, Cohere, Moonshot, MiniMax, Zhipu, DashScope, Hugging Face, NVIDIA NIM, GitHub Models, Replicate, Azure OpenAI and localhost servers such as Ollama and LM Studio. Granting the permission contacts nothing by itself. Browser control above does not need it.

3. Pair with the workspace

Paste the extension id and token into Settings → Browser extension in Synth Workspace. Pairing is one-time; regenerate to revoke old pages.
